# 문서 규격 (DOCUMENT)

독자의 질문에 답하는 제출용 최종본 기준.

## 1. 구조
- 독자·목적에 맞게 장을 정한다. 안내문은 선택 기준과 실행 순서, 분석문은 원인과 근거, 학습자료는 개념과 작동 원리를 채운다.
- 요약은 답·근거, 도입은 질문·범위, 본문은 설명, 결론은 다음 행동. 짧으면 요약·결론을 생략하고 결론에 새 사실을 넣지 않는다.
- 논점마다 주 설명 절을 정한다. 다른 절은 새 판단에 필요한 부분만 쓰거나 참조한다. 반복 장은 합치고 미확인 목록 장은 만들지 않는다.
- 제목·요약·결론의 강도와 범위를 본문에 맞춘다.
- 표지는 외부 제출·4쪽 이상·사용자 요구 때 기본. 짧은 내부 문서는 `cover: false`. 장절 번호는 복잡할 때만 쓴다(단독 1-1 금지).

## 2. 문체
- **범위는 처음부터.** `미국 건설관리자 전망`, `LH 개발 발표`처럼 주어에 범위를 넣는다. 넓게 단정한 뒤 일반화 금지 문장으로 물리지 않는다.
- **조건은 짧게, 한 번.** 표본·시점·목표 여부·발표 주체·비교 불가는 주장 옆 라벨이나 범위로 보존한다. 따로 읽히는 요약·표에는 필요한 조건을 다시 두되 해명 문단은 반복하지 않는다. 문서 전체의 한계는 한 곳에 둔다.
- 검증 경위·읽기 지시·주장 구분 강의는 빼고 판단에 필요한 조건만 남긴다.
- 사실·제안은 소제목이나 도입 한 번으로 구분한다. `이 가이드가 권하는`을 반복하지 않는다. 권고는 대상·조건·이유를 쓰고 자격의 존재를 채용 가치·우선순위로 키우지 않는다.
- 기능·작동·조건부터 설명한다. 반론은 선택을 바꿀 때만 한 곳에서 다룬다. 오해→부정→정답 구조를 반복하지 않는다.
- 같은 `A가 아니라 B`, 부정 뒤 재부정, 접속어로 방향을 거듭 뒤집는 문장은 직접 서술로 고친다. 의미·불확실성·주장 강도는 보존한다. 서로 다른 근거를 연결어미 하나로 묶지 않는다.
- 수식어·서술어를 대상에 맞추고 구체 행동을 쓴다. 00 밖 감정·경험·구어체와 균일한 문장·대구 소제목을 피한다.
- 본문 대시(—)는 문장 분리나 접속어로 바꾼다(제목·표·라벨 예외). 문단마다 요약·한계·시사점을 덧붙이지 않는다.
- 근거가 빈 곳은 판단을 바꾸는 공백만 한 번 밝힌다. `못 찾음`을 반박·부재의 증명으로 쓰지 않는다. 질문과 근거의 대상 범위를 맞춘다.
- 내부 이름·파일 번호·로그·경로는 쓰지 않는다. 조사·집필 지시는 본문 문장이 아니다.

본보기(최성호, 2020)는 기법만: 판단·사례·문답·출처 주체 소개. 문장·어조 복제 금지. 사례는 05에서, 가상은 표시.

## 3. 근거·출처
- 존재·사용·보급·효과·인과·경제성을 구분한다. 단일 사례를 업계 전체로, 근거 부족을 부재로 키우지 않는다. 같은 기준으로 비교하지 않은 대상에 순위를 매기지 않는다.
- 수치는 시점·단위·범위와 %/%p를 지킨다. 사실·계산은 05만 쓰며 새 계산·환산·보간 금지.
- 수치·법적 요건·인용·논쟁적 주장에 ID를 붙인다: `문장이다.[S03]`(PDF 위첨자). 같은 근거의 2~3문장은 끝에 묶고 주장 전체의 대응을 확인한다.
- 열람 범위·재인용 경위는 sources 자료명에 넣는다. 기업 자체 발표 등 판단을 바꾸는 성격은 본문에도 짧게 보존한다.
- 출처는 자료별 한 행, 자료 하나에 ID 하나. citation과 양방향 대응한다. 날짜가 없을 때만 미상, 로컬 경로는 숨긴다.

```markdown
::: sources 출처
S03 | 자료명 | 발행 주체 | 2026-09-20 | [원문](https://example.com)
S21 | 자료명 (ECB 2024 재인용) | 기관 | 미상 | 내부자료 p. 12
:::
```

검증된 직접 계산은 `계산: 본 보고서, S03 원자료 기준`(sources 행 없음), 비주얼은 `자료: 기관·자료명 (날짜).[S03]`.

## 4. 비주얼·편집
- 관계·추세·비교를 글보다 빨리 이해시킬 때만 쓴다. 비교는 표, 추세 line, 격차 bar/column, 단계 flow/timeline, 핵심 수치 stats. 직후 본문은 숫자를 재낭독하지 않는다.
- 실적과 목표는 라벨로 구분한다. 표·차트만 봐도 조건이 보이게 한다. 표 최대 6열, 셀 약 25자. 시간·비용 비교는 같은 범위·품질일 때만 한 축에 놓고, 다르면 자료 줄에 밝히고 배수로 말하지 않는다.
- 사용 수준과 효과를 한 등급으로 압축하지 않는다. 분류 기준과 근거·조건을 구분하고 모르는 칸은 `판단 자료 부족`.
- 사진은 현장·장비·결과물에 쓴다. 기본 본문 폭 68%·높이 80mm 이하, 분위기용 `{narrow}`, 세부 도식·지도만 `{wide}`. 쪽당 한 장, 높이의 1/3 이내.
- 사용자 색 우선, 없으면 절제된 accent·solid 표지·Pretendard. 홀로 남은 제목, 잘린 표·출처, 글자 겹침이 없다.

## 5. 마크업
지원: 제목 #~####, 문단, 불릿 2단계, 번호 목록, 표, 굵게·기울임·코드, 링크·인용, `---`, `<!-- pagebreak -->`, 그림. 임의 HTML·중첩 표·일반 각주 금지.
그림: `![캡션](경로 "크레디트")` 뒤 `{narrow}` 또는 `{wide}` 선택.
메타데이터: YAML `title`, `kind`, `date`, `org`, `cover`, `accent`, 선택 `accent2`.
블록: `::: summary 핵심 요약`, `::: stats`, `::: note`, `::: quote 출처`를 `:::`로 닫는다. stats 행은 `값 | 이름 | 조건`.
코드 블록: flow·timeline 행은 `단계/날짜 | 제목 | 설명`. chart는 `type: bar|column|line`, `title`, `unit`, `source`, `data:` 아래 `항목 | 값`; line 다계열은 `series: A | B`.
summary는 앞부분 1회, stats 2~4개, flow 2~5단계, quote 1~2회가 상한이다.
