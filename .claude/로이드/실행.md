# 로이드 실행 절차

호출 직전에 **필요한 절만** 읽는다 — `sed -n '/^## 4\./,/^## 5\./p' .claude/로이드/실행.md`

| 절 | 언제 |
| --- | --- |
| §0 | 경로 · 작업 시작 |
| §1 | 모드 판정 + 00 + 01 |
| §2 | 참고자료 (`자료/`가 있을 때만) |
| §3 | 유리 — 03 → 05 |
| §4 | 요르 — 조사 02 / 응답 04 / PPT 06 · 07 / PATCH |
| §5 | (DOC) 아냐 07 → `skills/doc-finish` |
| §6 | (PPT) `skills/deck-review` → `skills/notebooklm-handoff` |
| §7 | 최종 이관 |

## 0. 경로 · 시작
```bash
ID=<주제_YYYYMMDD>    # 웹앱 실행은 실행 계약의 작업 ID 그대로
mkdir -p "작업/$ID/workspace" "작업/$ID/sources" "작업/$ID/references" "작업/$ID/output"
```
python에 절대경로를 넘길 때는 `C:/...`로 쓴다(E-012). `상태.md`·`기록.md`는 `tools/stage.py`로만 쓴다(`로이드/상태파일.md`) — `init`부터.

## 1. 모드 판정 + 00 + 01
모드를 판정하고(애매하면 한 번 묻는다) `00`과 `01`을 **직접, 이어서** 쓴다. 에이전트는 부르지 않는다.
```markdown
# User Brief
- 작업 ID / 모드: DOCUMENT|PRESENTATION / 작성일
- 덱 유형: 스토리|학술|브리핑 (갈래) — PPT만. 판정 근거 한 줄
- 글 유형: <글유형.md의 값 하나> — DOC만. 선택 이유 한 줄
- 독자 도달점: <읽은 뒤 알거나 할 것> / 완료 기준: <확인 가능한 한 문장> — DOC만
- 보조 목적: <목적·사용할 절·필요한 기준 | 없음> / 편집: 단정|부드러움 / 말투: 평서체(기본)|해요체(사용자가 말로 요청했을 때만) — DOC만
- 원문 요청: (그대로)
--- 헤더 끝 ---
## 목적 · 결과물(형식·분량) · 주요 요구사항 · 대상 독자 · 필수 포함 · 제한사항
## 디자인 방향
- 톤: 전문적 ↔ 친근 ↔ 귀엽고 아기자기 (DOC는 색·표지에만. 문장은 `말투`)
- 이미지 비중: 높음 / 중간 / 낮음 · 이미지 방식: 사용자 제공 / 조사 수집(권리자 표기) / 생성 일러스트(PPT만) / 데이터·도식
- 캐릭터·인물 그림(PPT): 허용(초안용) / 금지 · 레퍼런스: references/ 경로 또는 "없음"
```
- 요구를 넓히지 않는다. 사용자가 말하지 않은 것은 `[추론]`으로 표시한다.
- **디자인 방향은 주제에서 추론하고, 사용자가 말하지 않은 제한을 만들지 않는다**(E-029). 스토리는 친근·이미지 높음·생성 일러스트, 학술은 전문적·이미지 낮음·데이터·도식, 브리핑은 전문적·데이터가 기본이다.
- **덱 유형은 소재가 아니라 목적으로 고른다**: ① 사용자가 말한 유형 ② 발표 맥락(수업·학회·경영진 보고·교육) ③ 목적 ④ 청중이 할 일 ⑤ 소재.
  위가 정해지면 아래로 바꾸지 않는다. ①~④가 비어 소재로만 정해야 하면 한 번 묻는다.
  예: 세미나에서 캐릭터 서사 분석 → 학술 · 논문으로 경영진에게 대응안 보고 → 브리핑 · 작품 세계관을 흥미롭게 소개 → 스토리
- **DOC는 `공통/글유형.md`와 선택한 `글_<이름>.md` 하나로 목적을 정한다.** 말투·편집은 별개로 고른다. 그림이 대상 이해의 핵심이면 이미지 방식 기본은 `조사 수집`이다.
- 이어서 `로이드/기획.md`로 `01`을 쓰고 그 §3 게이트를 통과해야 요르를 부른다.

## 2. 참고자료
```bash
python -c "
import fitz; d=fitz.open('자료/<파일>.pdf'); print('페이지',d.page_count)
for i in [0,d.page_count//2,d.page_count-1]: print(i+1,len(d[i].get_text()),'자 / 이미지',len(d[i].get_images()))"
```
텍스트가 0자인 구간은 dpi=150 PNG로 `작업/$ID/sources/<자료명>_pNNN.png`에 두고 조사 호출에 `--image`로 4~6장씩 붙인다. 위치는 PDF 기준 페이지로 적는다.

## 3. 유리 — 검증
**모델 값**: 호출 직전에 `DOCUMASTER_AGENT_MODELS`가 가리키는 JSON을 다시 읽어 `yuri.model`·`anya.model`을 그대로 쓴다.
환경변수가 없을 때만 기본값(유리 `sonnet`, 아냐 `opus`). 웹앱이 넘긴 파일은 경로 이름이 임시·스모크처럼 보여도 **현재 실행의 권위 있는 스냅샷**이다. 파일이 있는데 읽을 수 없거나 필드가 빠졌으면 호출하지 않고 오류를 보고한다.
역할 파일은 **붙여 넣지 않는다** — 경로만 주고 유리가 직접 읽는다(로이드 컨텍스트·출력 절약).
```
Agent(subagent_type:"general-purpose", description:"유리 검증 03", model:<유리 모델>,
  prompt: "너는 유리다. 먼저 .claude/유리/검증.md 와 .claude/공통/근거정책.md 를 읽고 그대로 따른다. 이번 호출: 03.
          입력: ./작업/<ID>/workspace/00_user_brief.md · 01_research_blueprint.md · 02_research_pack.md
          출력: ./작업/<ID>/workspace/03_verification_questions.md 에 직접 저장. 응답은 헤더만.")
```
반환된 에이전트 ID는 03을 마친 `stage.py done 03 --session "유리 에이전트=<id>"`에 넣는다. 03은 헤더와 「상한에 막혀 못 본 것」만 읽는다(전문을 옮겨 쓰지 않는다).
판정은 **같은 에이전트에** 보낸다 — `SendMessage(to:"<유리>", message:"이번 호출: 05. 입력: ./작업/<ID>/workspace/04_verification_answers.md (+02 최신 버전). 출력: ./작업/<ID>/workspace/05_verified_research_pack.md 에 직접 저장. 응답은 헤더만.")` — 05는 파일로 정독한다. `answer`의 02 패치가 재시도까지 실패하면 02 다음 버전 없이 05로 간다. 유리에게 04의 수정을 05에 직접 반영하라고 적어 보낸다(E-058).
에이전트가 이미 끝났으면 새로 띄우고 파일과 경로를 전부 다시 준다.
**채택 전** `python .claude/tools/gate_check.py "$ID" 05` — FAIL(구조·출처 누락)은 유리에게 한 번 돌려 `05_…_v02`로 받는다. §2 표현 CHECK는 집필 지시와 주제의 정의·법적 조건을 구별해 닫는다(판정 유지, 표기만 보완).

## 4. 요르 (Codex) — `python .claude/tools/yor.py <종류> --id "$ID"`
모델·강도(스냅샷 재독)·입력 인라인(E-051)·세션 저장·읽기 전용·결과 대조는 도구가 한다. **codex를 직접 부르지 않는다.**
마지막 줄 `요르 <종류>: OK|FAIL`과 출력 파일을 함께 본다. 세션 ID는 yor.py가 `_yor_sessions.json`에 남기고 `stage.py`가 `상태.md`로 옮긴다.

| 종류 | 언제 | 먼저 쓸 지시 `작업/$ID/…` | 결과 |
| --- | --- | --- | --- |
| `research` | 01 게이트 뒤 | `_입력_조사.md`(선택) | 02 · 조사 세션 |
| `answer` | 03 저장 뒤 | `_입력_응답.md`(선택) | 04 + 02 다음 버전 |
| `plan` | PPT · 05 채택 뒤 | `_입력_세부기획.md`(**필수** — 05 §4 결정) | 06 · 기획 세션 |
| `pack` | PPT · 06 게이트 뒤 | `_입력_비주얼기획.md`(자산·지정 스타일) | 07 발표팩 |
| `patch --target <파일>` | 반려 | `_입력_patch.md`(**필수** — 고칠 항목만) | 대상 다음 버전 |

- Bash `timeout: 600000`, **포그라운드**로 부른다. 시간 제한으로 백그라운드에 넘어가면 턴을 끝내지 말고 `yor.py wait --id "$ID"`를 반복한다(75 = 진행 중). 새 호출 금지.
- 적용기 실패는 출력된 「가장 가까운 줄」을 지시 파일에 옮겨 `--retry`로 **한 번만** 돌려준다. 적용 뒤 헤더 수치와 절 사이 값을 본다.
- 한도(E-013)면 모델을 바꾸지 말고 기다리거나 사용자에게. 종료 코드 3(모델 불일치)은 채택하지 않고 보고한다. **DOC는 요르 기획 없이 §5로.**

**PPT 06 게이트** — `gate_check.py "$ID" 06` 뒤 06 전체를 읽는다. FAIL(되살아난 REMOVE·빠진 CAUTION·LOCKED 위반)은 그 항목만 `patch`로,
05에 없는 수치는 근거가 없으면 뺀다. 읽으며 볼 것: `요르/세부기획.md` §3 · 표현만 바꾼 REMOVE · 강도. CHECK는 닫은 이유를 기록.md에.

**반려는 담당에게** — 로이드가 직접 고치는 것은 기계적 수정(오탈자·형식·필드 누락·강도 낮추기)과 PPT 화면 문구뿐. `기록.md`에 `대상 · 이유 · 담당 · 요청` 한 줄.
(PPT) 장 수·순서·메시지·근거 배분 → 요르 06 · 톤·색·서체·주인공·구성 → 요르 07 · (DOC) 구조·문장·마크업 → 아냐 ·
NotebookLM이 설계와 다름 → `nlm slides revise` · 사실·수치·강도 → 근거 단계

## 5. DOC — 아냐 07
호출 직전에 모델 JSON을 다시 읽고 `anya.model`을 그대로 쓴다(§3과 같은 규칙).
```
Agent(subagent_type:"general-purpose", description:"아냐 문서 07", model:<아냐 모델>,
  prompt: "너는 아냐다. 먼저 .claude/아냐/문서작성.md 와 .claude/공통/문서규격.md 를 읽고 그대로 따른다.
          입력(이것만): ./작업/<ID>/workspace/00_user_brief.md · 05_verified_research_pack.md(첫 줄·§2·§5만)
          글 유형 파일: .claude/공통/글_<선택한 이름>.md · 이미지 목록: ./작업/<ID>/references/images.md (없으면 빼기)
          독자 한계: <명사구 ≤2개 | 없음>
          출력: ./작업/<ID>/workspace/07_final_document.md 에 직접 저장. 응답은 작성 보고 3~6줄.")
```
이미지 방식이 `조사 수집`이면 먼저 `python .claude/tools/fetch_images.py "$ID"` — 02 §I를 받아 `sources/images/`·`references/images.md`·`images_contact.png`를 만든다. 모아보기를 보고 캡션과 다른 그림·팬아트·워터마크 그림은 images.md에서 `제외`로 바꾼다.
부르기 전에 05 §4를 로이드가 닫는다. **독자 한계**는 이해·판단·실행을 바꾸는 공백만 고른다. 나머지 미확인은 넘기지 않는다.
00의 주제 축(예: 정치·경제의 한쪽)이 05에서 일정·목록 수준으로 줄었으면 사용자에게 한 번 묻는다(보강 조사 / 제목 축소).
반환된 에이전트 ID는 07을 받은 `stage.py done 07 --session "아냐 에이전트=<id>"`에 넣는다. 호출하지 않는 역할은 `해당 없음(<이유>)`으로 쓴다.
한도(429)에 걸리면 새로 띄우지 말고 리셋 뒤 `SendMessage`로 재개한다(E-011). 이어서 `skills/doc-finish`로 간다.

## 6. PPT — 발표팩 검수 → NotebookLM
1. `skills/deck-review` — 흐름·비주얼·화면 문구를 보고, 화면 문구는 로이드가 직접 다듬는다.
2. `skills/cross-check` — 크게 박힌 수치와 강도.
3. `skills/notebooklm-handoff` — `python .claude/tools/nlm_pipeline.py check`부터.

NotebookLM을 끝내 못 쓰면 발표팩까지만 완성하고 보고한다. pptx 직접 제작(E-038)은 사용자가 지시할 때만 쓰고, "이미지 비중 목표는 달성하지 못한다"를 먼저 알린다.

## 7. 최종 이관 — `최종/<유형>/<ID>/`
**판정이 passed/conditional이고, 기계 검사를 통과했고, 교차 확인이 닫혔고, CAUTION의 조건이 최종본에 살아 있을 때만** 실행한다.
```bash
KIND=<00의 글 유형에서 가운뎃점을 뺀 이름>   # 현황기록·설명해설·분석·평가비평·제안설득·안내절차·서사소개
mkdir -p "최종/$KIND/$ID" && cp "작업/$ID/output/$ID.pdf" "최종/$KIND/$ID/$ID.pdf"    # DOC
python .claude/tools/nlm_pipeline.py promote --id "$ID"                   # PPT (검사 미통과·팩에 없는 숫자가 있으면 보류. 직접 닫았을 때만 --force)
python .claude/tools/stage.py finish --id "$ID" --final "최종/$KIND/$ID/<파일>" --manifest "<파일명 (비고)>"   # PPT는 --manifest 빼기(도구가 씀)
```
`finish`가 세션 자리표시자로 멈추면 실제 ID 또는 `해당 없음(이유)`으로 닫고 다시 부른다. 그다음 `CLAUDE.md` §7대로 보고한다.
