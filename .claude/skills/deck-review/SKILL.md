# 발표팩 검수 — NotebookLM에 넘기기 전 마지막 지점

NotebookLM은 준 대로 그린다. 기준은 `공통/발표규격.md`와 00의 덱 유형 파일(`공통/발표_<유형>.md`)이다. 먼저 `python .claude/tools/gate_check.py "$ID" 07`을 돌려
장 수·Character Model·출처 표시·제목 중복·REMOVE·수치를 기계로 닫는다(FAIL은 §4 조치로). 그다음 **07을 한 번 읽으면서** 아래를 같이 보고, 교차 확인 후보(크게 박힌 수치·인용)도 그때 `기록.md`에 적어 둔다.

## 1. 흐름 — Main Message만 이어 읽는다 (발표규격 §1)
- 논지가 서는가, 목차 낭독인가? 00의 덱 유형이 목적·청중에 맞고(소재가 아니라), 흐름·닫는 방식이 유형 파일 §1을 따르는가? 유형 파일 §6의 흐름 질문에 답이 되는가?
- 청중이 모를 인물·용어가 정의 없이 나오지 않는가(유형 파일이 요구할 때)?
- Key Takeaways가 본문 장에서 실제로 나오는가(결론에만 나오는 주장은 없는가)?

## 2. 비주얼 — 발표규격 §6과 유형 파일 §7의 재작업 대상을 장마다 대조한다
특히 볼 것: 주인공이 유형 파일 §2의 크기로 먼저 보이는가 · 수치 장에 무엇을 센 숫자인지 한 줄이 있는가 · 겉모습이 주제에서 나왔는가(이전 작업·레퍼런스 복제 아님).
유형 파일 §5의 「화면」 요구(장면 속 글자 자리, 또는 장마다 패턴 하나와 데이터 옆 해석)를 채웠는가. Character Model·화풍 일치(E-036·E-046)·줄 길이는 gate_check가 본다.

## 3. 화면 문구 — 로이드가 직접 다듬는다 (FLEX)
「제목」·「화면 문구」만 고친다. **의미·강도·사실은 바꾸지 않는다.**
- 호흡 단위로 끊는다. 목록 항목 하나가 화면의 한 줄이다. 조사·수식어 뒤에서 끊지 않는다.
- 제목과 문구가 같은 문장이면 하나를 지운다. 제목을 "없음"으로 둘 수 있는지는 유형 파일 §3대로다. 제목을 다듬어도 강도는 올리지 않는다.
- 출처를 옮기거나 지우는 것은 유형 파일 §6이 허용할 때만이다.
- 한정은 한 줄(30자 이내)로 줄이고, 넘치는 조건은 발표자 메모로 보낸다(삭제하지 않는다). 화면에 없는 것을 가리키는 한정은 청중이 알아듣게 고친다.
- 번역투를 고친다. 말투와 길이는 유형 파일 §6대로다.

## 4. 조치
| 문제 | 조치 |
| --- | --- |
| 화면 문구 (§3) | 로이드가 바로 고친다. `기록.md`에 몇 장을 어떻게 고쳤는지 한 줄 |
| 메시지가 근거보다 세다 | 로이드가 **낮추는 쪽으로만** 고치고 원문과 함께 기록한다 |
| 비주얼 설계 (§2) | 요르 기획 세션에 **문제 장만** 지정해 PATCH |
| 흐름·구조 (장 추가·삭제·순서, 오프닝·마무리 재설계) | 요르 06 → 06B 변경분만 PATCH |

새 사실을 요구하지 않는다. `05`에 없는 것이 필요하면 조사 부족이다 — 사용자에게 올린다.
