# 절차 — 비주얼 기획 DOCUMENT (요르 06B) · 출력 `06_visual_direction.md`

06 기획 세션을 resume해서 부른다. 06의 내용을 편집 디자인으로 옮기는 지시서이고, 아냐가 이대로 마크업한다.
기준은 06에서 이미 받은 `공통/문서규격.md` §3이다. 렌더러(`tools/md2html.py`)는 **지정한 것만 정확히 그린다** — 아냐가 판단할 여지를 남기지 않는다.

## 1. 원칙
- 새 사실과 계산값을 넣지 않는다. 06의 구조·메시지·한정은 바꾸지 않는다. 바꿔야 하면 「06에 올릴 문제」에 적는다.
- accent는 이 주제에서 나온 색이다. 이전 문서의 색을 가져오지 않는다.
- 자산은 05에 출처가 있는 것과 사용자가 준 것(`자료/`·`references/`)만 쓴다.

## 2. 쓸 수 있는 요소 — 이 목록 밖은 없다
표지(색 / 사진 — 사진은 검증된 자산이 있을 때만) · `::: summary` 요약(앞에 한 번) · `::: stats` 핵심 수치 2~4개 ·
`chart` bar / column / line(3계열까지) · `timeline` · `flow`(2~5단계) · 표 · `::: quote`(문서 전체에 1~2번) ·
`::: note` 한정 · 그림(검증된 자산만).

## 3. 형식

```markdown
# Visual Direction
- 작업 ID / 대상 06 버전 / 기획 개정 번호 / 모드: DOCUMENT
--- 헤더 끝 ---
## A. Art Direction
- 인상: 한 문장
- accent: #RRGGBB (주제에서 나온 이유, 흰 배경 대비 4.5:1 이상) · accent2: #RRGGBB (한정 표시 전용)
- 표지: solid | photo(자산 ID) · kind · subtitle · date · org
- 피할 것
## B. 자산 (없으면 "검증된 자산 없음")
## C. 읽기 리듬 — 장마다 핵심 시각 요소 하나, 같은 요소가 세 장 연속되지 않게
# Chapter Plan
## 1. <06의 장 제목 그대로>
- Key Visual: 요소 + 고른 이유 한 줄 (없음이면 이유)
- 데이터: 항목 | 값 (근거 ID) · 단위 · 시점 · 범위 · 강조 항목
- 위치: 어느 절 어느 문단 뒤
- 캡션·출처: 제목 · 단위 · `자료:` 줄
- 한정: 06 그대로 + 자리
# 06에 올릴 문제 (없으면 "없음")
```

## 4. 제출 전 점검
- accent가 주제에서 나왔고 대비가 4.5:1 이상인가?
- 모든 장에 Key Visual이 있거나, 없는 이유가 적혀 있는가?
- 차트 값이 06·05 그대로인가?
- 표가 표 기준에 맞는가?
- 본문만 두 쪽 넘게 이어지는 구간이 없는가?

전문을 마지막 응답 본문으로 반환한다.
