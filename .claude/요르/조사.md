# 절차 — 조사 (요르) · 출력 `02_research_pack.md`

근거 유형·확인 상태·수치 조건·출처 충돌·할루시네이션 유형은 `공통/근거정책.md`에 있다. 여기서 반복하지 않는다.

## 1. 범위

`01_research_blueprint.md`의 **조사 질문에 답하는 것**이 목적이다. 백과사전을 만들지 않는다.

- **발견 레인(최대 3건):** 기획을 바꿀 만큼 중요한데 질문에 없는 발견이 있으면 §H에 제안한다.
  근거 ID와 왜 기획을 바꿀 만한지 한 줄씩 적는다. 없으면 "없음"이라고 쓴다. 채우려고 만들지 않는다.
- DOC는 01의 글 유형·독자 도달점·완료 기준에 필요한 재료를 조사한다. 정의·원리·예시·절차·장면도 검증할 사실이다. 비교·반론·원인 분석은 요청한 목적에 필요할 때 확보한다. PPT는 덱 목적에 맞춘다.
- 정의·법령·통계는 1차 출처로 충분하다. 현황·사례·동향처럼 전체를 판단하는 질문은 한 갈래(기관 자료만, 리뷰 논문만)에서 멈추지 않고
  국내외 논문·기관 자료·기사 가운데 다른 갈래도 확인한다. "없다"는 어디서 찾았는지와 함께 쓴다(E-068).
- 핵심 논점은 값과 함께 **원인·배경·작동 방식(왜 그런가, 어떻게 이어지나)**을 근거로 확보한다. 최종 글은 05에 있는 것으로만 설명할 수 있어서, 여기서 빠진 배경은 글에서 설명이 빠진 채로 남는다(E-067). 출처가 그 이유를 직접 말하는지 확인하고, 네 추론이면 `[해석]`으로 둔다.
- 핵심 수치의 출처가 `pwc.com`·`weforum.org`·`hbs.edu`(E-056 — 로이드·유리가 못 연다)이면 근거표에 **원문 구절을 그대로(쪽·절 포함)** 인용해 둔다.
- 발표 모드이고 캐릭터·인물이 나오면, 공식 외형 묘사(색·형태·식별 특징)를 근거로 확보한다. 발표팩(07)의 Character Model이 이것만 쓸 수 있다.
- 00의 이미지 방식이 `조사 수집`이면 §I에 그림 후보 6~12개를 모은다. 공식 사이트·공식 계정·출판사·보도자료·위키미디어 순으로 찾는다. 팬아트·AI 생성·권리자 불명은 넣지 않는다.
  이미지 URL은 파일로 바로 열리는 주소(.jpg·.png·.webp)이고, 네가 실제로 본 것만 적는다. 표지 후보를 하나 이상 넣는다. 파일은 로이드가 내려받는다.

## 2. 출력 형식 — 바꾸지 않는다 (로이드는 헤더만, 유리는 절 기호로 대조한다)

```markdown
# Research Pack
- 작업 ID / 조사 버전 / 적용 기획 개정 번호 / 모드:
- 참고자료 읽은 범위 / 못 읽은 범위 (없으면 "참고자료 없음"):
- 웹 검색 사용 가능 여부:
- 근거 확인: 외부 n/n · 로컬 n/n · 계산 n/n
- 기획 보정 제안: n건 · 미확인 필수 항목: n건
--- 헤더 끝 ---

## A. Executive Findings      핵심 5~8줄, 줄마다 근거 ID
## B. Detailed Findings       ### Q1. <질문> — 답 / 근거 ID / 확인 상태 / 남은 불확실성
## C. Evidence Table          값과 조건의 원본. 다른 절은 ID로 참조한다
| ID | 주장 | 출처 제목 | 발행 주체 | 발행일 | 근거 위치 | 확인 상태 | 비고(값·단위·시점·범위·본문 구절) |
## D. Conflicting Evidence    항목 / 각 값과 조건 / 차이 원인 / 채택 보류 — 로이드 판단
## E. Unverified Claims       항목 / 못 한 이유 / 필수 여부 / 필요한 확인
## F. Important Numbers       | 값 | 단위 | 기준 시점 | 집계 범위 | 근거 ID |
## G. Sources                 ID · 제목 · 발행 주체 · 발행일 · URL(접속일) · 1차/2차
## H. 기획 보정 제안           발견 / 근거 ID / 확인 상태 / 이유 / 제안 조치 (없으면 "없음")
                              01 「확인할 전제」마다 한 줄: 지지 / 반대 / 미확인 + 근거 ID (반대는 3건 한도와 별개로 항상 적는다)
## I. Images                 (이미지 방식이 조사 수집일 때만) | I01 | 이미지 URL | 출처 페이지 URL | 무엇(대상·장면) | 권리자 | 쓸 곳(표지·장) |
```

결과물 구조는 여기서 짜지 않는다. DOC는 아냐 07, PPT는 요르 06에서 한다.

## 3. 제출 전 점검

근거정책 §6을 네 원고에 대고 훑은 뒤 아래를 확인한다 — 모든 질문에 답했는가(답 못 한 것을 답한 척하지 않았는가),
열지 않은 것을 `[확인됨]`으로 적지 않았는가, 수치마다 단위·시점·범위가 있는가, 보간한 값이 없는가,
충돌을 하나로 확정해 버리지 않았는가, §C의 값과 §A·§B·§F의 값이 일치하는가.
