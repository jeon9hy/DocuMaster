# 절차 — 세부 기획 (요르) · 출력 `06_detailed_plan.md`

검증이 끝난 사실(`05_verified_research_pack.md`)로 **무엇을 어떤 순서로 말할지** 확정한다. 다음 사람이 "무엇을 쓸지" 더 판단할 게 없어야 한다.
어떻게 보일지(표·차트·카드·레이아웃)는 06B가 정한다. **여기서 형식 이름을 쓰지 않는다**(E-026).

## 1. 근거와 경계

- 근거는 **`05`뿐이다.** 새로 조사하지 않는다. 채워야 하는데 `05`에 없으면 문서 끝 「완성 못 한 항목」에 적는다.
- REMOVE는 자리를 비우거나 인접 항목과 합친다. CAUTION은 **어느 절·슬라이드의 어느 문장 옆에** 들어가는지 지금 정한다.
- 계산값을 새로 만들지 않는다(`05`에 없는 증감률·비율은 새 수치다).
- **LOCKED / FLEX:** 사실·수치·조건·근거 배분·CAUTION·개수와 순서·제목·주장 강도는 LOCKED다(표시하지 않는다).
  문장 표현·전환·중복 제거·길이 조정처럼 열어 줄 것에만 `(FLEX)`를 붙인다.
- **강도는 절대 FLEX가 아니다.** `05`가 전후 비교라면 지시도 전후 비교로 쓴다. 네가 쓴 강도가 최종 문장의 강도가 된다(E-021).

## 2. 출력 — DOCUMENT

```markdown
# Detailed Plan
- 작업 ID / 대상 05 버전 / 기획 개정 번호 / 모드: DOCUMENT
- 근거: 05만
--- 헤더 끝 ---
## 문서 구조      제목 / 부제 / 예상 분량
## 장별 지시
### 1. <장 제목 — 확정>
- 장 첫 문단의 결론 한 문장
#### 1-1. <절 제목 — 확정>
- 다룰 순서: 1) … 2) … — 항목마다 근거 ID와 그것이 뒷받침하는 문장 1줄
- CAUTION: 어느 문장 뒤에, 어떤 문구(05 그대로)
- 보여 줄 비교·수치·시간 순서가 있으면 그 데이터와 근거 ID (형식은 06B가 고른다)
- 분량: n문단
## 한계와 가정 절 지시
## 출처 절 지시 (05 §3에서 옮긴다)
## 완성 못 한 항목 (없으면 "없음")
```

## 3. 출력 — PRESENTATION

덱은 논지 하나다(`공통/발표규격.md` §1). **함께 받은 덱 유형 파일(`발표_<유형>.md`) §1의 흐름 틀로 장을 채운다.**

```markdown
# Detailed Plan
- 작업 ID / 대상 05 버전 / 기획 개정 번호 / 모드: PRESENTATION
- 덱 유형: 스토리 | 학술 | 브리핑 (00 그대로)
- 슬라이드 수: n
--- 헤더 끝 ---
## 1. Goal · Audience          각 한 줄
## 2. Core Logic                3~5줄. 핵심 질문 · 핵심 근거 · 청중이 끝에서 이해·판단·행동할 것
## 3. Deck Arc
- 오프닝: 표지와 2장이 여는 것(유형 파일 §1대로)
- 중심 장: 몇 번 장이고 무엇인가(유형 파일 §1의 중심)
- 마무리: 결론과 닫는 방식(유형 파일 §1대로)
## 4. Key Takeaways (3~5)

## Slide 1 — <Beat: 유형 파일 §1 흐름의 단계>
- 메시지: 청중이 기억할 한 문장 (확정)
- 제목: 화면 제목. 호흡 단위 줄바꿈을 ` / `로 표시한다. "없음"을 쓸 수 있는지·제목 형식은 유형 파일 §3대로
- 내용: 전달할 사실·수치·관계 3개 이내(참고문헌·출처 장 제외). 항목마다 근거 ID, 수치는 값·단위·시점·범위까지
- 한정: 화면에 남길 한계 한 줄(30자 이내, 05 CAUTION에서) 또는 "없음"
- 출처 표시: 예 | 아니오 — 유형의 출처 기준대로
- 발표자 메모: 배경·검증 경위·원작 회차 같은 참조 (화면에 나오지 않는다)
- 금지선: 이 장에서 넘으면 안 되는 표현이나 강도

## 근거 목록
| ID | 주장 | 출처(사람이 읽는 기관·자료명) | 발행일 | URL |
## 완성 못 한 항목 (없으면 "없음")
```

- 제목과 메시지·내용이 같은 말을 되풀이하지 않게 한다. 앞 장에서 화면에 나온 사실을 다음 장에서 반복하지 않는다(유형 파일이 허용한 논의·결론 장 예외).
- 검증 경위는 한정이 아니라 발표자 메모에 둔다. 한정은 화면에 뜬다.

## 4. 제출 전 점검 — 하나라도 "그렇다"면 미완성이다

- 제목·순서·분량 중 "적절히" 같은 판단을 넘기는 자리가 남았는가?
- CAUTION 중 위치가 지정되지 않은 것이 있는가? REMOVE 자리를 처리했다고 명시하지 않았는가?
- 숫자를 "05 참고"로 넘기고 근거 ID로 지정하지 않았는가?
- 형식 이름(표·카드·차트 종류)을 적었는가?
- 지시의 강도가 `05`를 넘는가? 상관을 인과로, 권고를 확정으로 썼는가?
- (발표) Main Message만 이어 읽을 때 논지가 서는가? 흐름이 유형 파일 §1과 다른가? 결론이 앞 장의 나열인가?
- (발표) 청중이 모를 인물·용어가 정의 없이 나오는가(유형 파일이 정의를 요구할 때)?

전문을 마지막 응답 본문으로 반환한다.
