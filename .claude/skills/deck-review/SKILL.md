# 발표팩 검수 — NotebookLM에 넘기기 전 마지막 지점

NotebookLM은 준 대로 그린다. 기준은 `공통/발표규격.md`다. 먼저 `python .claude/tools/gate_check.py "$ID" 07`을 돌려
장 수·Character Model·출처 표시·제목 중복·REMOVE·수치를 기계로 닫는다(FAIL은 §4 조치로). 그다음 **07을 한 번 읽으면서** 아래를 같이 보고, 교차 확인 후보(크게 박힌 수치·인용)도 그때 `기록.md`에 적어 둔다.

## 1. 흐름 — Main Message만 이어 읽는다 (발표규격 §1)
- 이야기가 되는가, 목차 낭독인가? 결론이 근거 뒤에 오는가?
- 첫 장이 주제의 얼굴이고 2장이 왜 들어야 하는지를 여는가? 마지막 장이 표지 모티프를 받아 결론 한 문장으로 닫는가?
- 절정 장이 있는가? Key Takeaways가 본문 장에서 실제로 나오는가(결론에만 나오는 주장은 없는가)?

## 2. 비주얼 — 발표규격 §6 재작업 대상을 장마다 대조한다
특히 볼 것: 비데이터 장의 주인공이 50% 이상인가. Character Model 일치(E-036)는 gate_check가 본다.

## 3. 화면 문구 — 로이드가 직접 다듬는다 (FLEX)
「제목」·「화면 문구」만 고친다. **의미·강도·사실은 바꾸지 않는다.**
- 호흡 단위로 끊는다. 목록 항목 하나가 화면의 한 줄이다. 조사·수식어 뒤에서 끊지 않는다.
- 제목과 문구가 같은 문장이면 하나를 지운다. 그림이 말하는 장이면 제목을 "없음"으로 둔다.
- 장면·줄거리 장의 출처는 「발표자 메모」로 옮긴다.
- 한정은 한 줄(30자 이내)로 줄이고, 넘치는 조건은 발표자 메모로 보낸다(삭제하지 않는다).
- 번역투와 딱딱한 문장을 발표 말투로 짧게 고친다.

## 4. 조치
| 문제 | 조치 |
| --- | --- |
| 화면 문구 (§3) | 로이드가 바로 고친다. `기록.md`에 몇 장을 어떻게 고쳤는지 한 줄 |
| 메시지가 근거보다 세다 | 로이드가 **낮추는 쪽으로만** 고치고 원문과 함께 기록한다 |
| 비주얼 설계 (§2) | 요르 기획 세션에 **문제 장만** 지정해 PATCH |
| 흐름·구조 (장 추가·삭제·순서, 오프닝·마무리 재설계) | 요르 06 → 06B 변경분만 PATCH |

새 사실을 요구하지 않는다. `05`에 없는 것이 필요하면 조사 부족이다 — 사용자에게 올린다.
