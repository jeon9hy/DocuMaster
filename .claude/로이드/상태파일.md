# `상태.md` · `기록.md` 양식

`상태.md`에는 재개에 필요한 것만 둔다. 세션 시작 때 첫 3줄만 읽으므로, **판단에 필요한 것을 첫 3줄에** 둔다.
지나간 판정과 해소된 쟁점은 `기록.md`로 옮긴다.

## 상태.md
```markdown
# <작업ID> — <한 줄 주제> · 모드: DOCUMENT|PRESENTATION
상태: 진행 중 <단계> | 사용자 승인 대기 | 완료 | 중단
다음에 할 일: <한 줄>

## 요청      독자 / 분량 / 형식 — 상세는 workspace/00
## 기획      개정 번호 r1 · 핵심 메시지 · 질문 수
## 진행      | 단계 | 산출물 | 상태 | 비고 |  (00·01 / 02 / 03·04·05 판정 / DOC 07 또는 PPT 06·07 / 산출·기계 검사 / Lite Review·교차 확인)
## 세션      요르 조사 세션 ID · 요르 기획 세션 ID · 유리 에이전트 · 아냐 에이전트 · 실제 모델(확인 불가면 미확인)
## 열린 것   검증 라운드 0/1 · 자료 보완 0/1 · 채택할 것 · REMOVE·CAUTION 목록 · 교차 확인 n/n · 사용자 결정 대기
```

**직접 Edit하지 않고 `tools/stage.py`로 쓴다** — 단계가 바뀔 때만 한 번, 상태 줄·다음 할 일·진행 표·세션 ID와 기록 한 줄을 함께. 호출 사이사이에 고치지 않는다(E-055).
```bash
python .claude/tools/stage.py init --id "$ID" --topic "<한 줄 주제>" --mode DOCUMENT      # §0에서 한 번(양식 생성)
python .claude/tools/stage.py done 03 --id "$ID" --output workspace/03 --note "유리, 질문 5건"   --status "진행 중 04 응답" --next "요르 answer" --session "유리 에이전트=<id>" --log "유리 03: <요약>"
python .claude/tools/stage.py set --id "$ID" --status "사용자 승인 대기" --open "<열린 것 전체>"   # 행 없이 칸만
python .claude/tools/stage.py log --id "$ID" "<기록 한 줄>"                                       # 기록.md만
python .claude/tools/stage.py finish --id "$ID" --final "최종/$KIND/$ID/$ID.pdf" --manifest "<파일명 (비고)>"   # $KIND=글 유형(PPT는 발표)
```
요르 세션 ID는 도구가 `_yor_sessions.json`에서 옮긴다. `finish`는 `--final` 파일이 없거나 세션 칸에 `(실행 후 기록)`·`(미실행)`이 남으면 멈춘다 — 모드상 호출하지 않는 역할은 `해당 없음(DOC|PPT)`처럼 이유를 쓴다.

## 기록.md
시간순으로 **덧붙이기만** 한다. 판정이 난 단계마다 한 번에 모아 적는다. 남길 것은 호출(모델·세션·종료 코드), 헤더 수치, 판정과 이유, 채택 결정, 반려,
교차 확인 결과(값 · 근거 ID · 원문 대조), 강도를 내린 문장의 원문과 수정문, 실패한 호출과 원인, 사용자에게 올린 것과 답이다.
