# 글 — 목적에 따른 분기

DOC 기획에서 이 파일과 선택한 `글_<이름>.md` 하나를 읽는다. 아냐·doc-finish에는 문서규격과 선택한 파일만 싣는다. 본보기 원문·유지보수 자료는 실행 입력이 아니다(E-063).

## 1. 선택
사용자가 명시한 목적 → 읽은 뒤 독자가 알거나 할 일 → 요청의 질문 순으로 주목적 하나를 고른다. 보고서·칼럼·학습자료는 결과물 형식이고, 평서체·해요체는 말투다. 소재·제출 여부·독자의 친밀도로 목적을 정하지 않는다.

| 글 유형(00·07의 값) | 독자가 얻을 것 | 파일 |
| --- | --- | --- |
| 현황·기록 | 무엇이 언제 어디까지 진행됐는지 | 글_현황기록.md |
| 설명·해설 | 무엇이며 어떻게 작동하는지 | 글_설명해설.md |
| 분석 | 차이·변화·관계를 설명하는 답 | 글_분석.md |
| 평가·비평 | 기준에 비춘 가치·성취·문제 판단 | 글_평가비평.md |
| 제안·설득 | 받아들일 주장·선택과 그 이유 | 글_제안설득.md |
| 안내·절차 | 조건에 맞게 일을 끝내는 방법 | 글_안내절차.md |
| 서사·소개 | 구체적인 대상·사건과 그 맥락 | 글_서사소개.md |

혼합 글은 주목적 하나와 보조 목적·사용할 절을 00에 적는다. 보조 목적의 필수 재료는 01 질문에 반영하고 필요한 기준만 00에 옮긴다. 유형 파일을 전부 싣지 않는다. 목적을 바꾸면 로이드가 00·기획 개정을 갱신한다.
질문이 충분하면 선택 이유를 한 줄 적고 진행한다. 서로 다른 목적이 필수 내용·조사 범위를 바꾸는데 요청으로 결정할 수 없을 때만 묻는다.

## 2. 같은 소재의 다른 글
- `AI 활용 현황을 알려줘` → 현황·기록. 사용 범위·시점·진행 상태.
- `AI가 어떻게 답을 만드는지 알려줘` → 설명·해설. 개념·과정·예시.
- `AI 도입 성과가 조직마다 왜 다른가` → 분석. 비교 조건·요인·관계.
- `우리 AI 도입은 잘됐나` → 평가·비평. 목표·판정 기준·실적.
- `어떤 AI 도입안을 선택할까` → 제안·설득. 대안·조건·선택 이유.
- `AI 도구를 처음 사용하는 방법` → 안내·절차. 준비·순서·완료 확인.
- `AI를 만드는 연구팀을 소개해줘` → 서사·소개. 사람·장면·맥락.

작품 소개는 서사·소개, 작동 원리 소개는 설명·해설, 작품의 성취를 논하는 평론은 평가·비평이다. `왜 인기인가`는 분석, `어떤 매력이 있는가`는 소개나 비평인지 요청의 초점을 본다.

## 3. 편집과 이전 작업
새 작업의 00에는 `글 유형`, `독자 도달점`, `완료 기준`, `편집: 단정|부드러움`, `말투: 평서체|해요체`를 적는다. 표현·편집은 문서규격을 따른다. `읽을거리`를 독립 목적 분기로 쓰지 않는다.
이전 00에 `문서 유형: 보고서|읽을거리`만 있으면 기존 결과물은 그대로 검사·렌더한다. 이어 집필할 때 로이드가 목적을 판별해 00에 보완하고 같은 계약으로 07을 쓴다. 보고서를 분석으로, 읽을거리를 서사로 자동 대응하지 않는다.
