# 절차 — Research Blueprint (로이드) · 출력 `01_research_blueprint.md`

`00`을 쓴 세션에서 이어서 쓴다. **짧은 계획이다.** DOC는 선택한 글 유형의 `기획·조사 재료`와 `완료 기준`을 질문으로 옮긴다. 요르는 이 계획으로 필요한 재료를 조사한다.

## 1. 원칙
- **조사 질문이 전부다.** "AI 시장 동향" ✗ / "국내 생성형 AI 기업용 시장 규모는 2024년 기준 얼마이고 누가 집계하나" ○
- 질문은 5~10개로 잡는다. 결과물에 들어갈 것만 묻는다. 요청 범위를 넓히지 않는다. 추론한 항목은 `[추론]`으로 표시한다.

## 2. 형식
```markdown
# Research Blueprint
- 작업 ID / 기획 개정 번호(r1) / 모드 / 조사 질문 수
--- 헤더 끝 ---
## 1. 사용자 목적        한두 줄
## 2. 결과물 형태        종류·분량·제약 / DOC 글 유형·독자 도달점·완료 기준(00과 같게)
## 3. 독자              누구이고 무엇을 알고 무엇을 알고 싶은가
## 4. 핵심 질문과 잠정 답 DOC는 유형에 맞는 상태·개념·설명 가설·평가 질문·선택·완료 작업·소개 초점. 답이 없으면 질문만. PPT는 핵심 메시지 가설
   확인할 전제          | # | 전제(메시지가 기대는 사실 주장) | 틀리면 바뀌는 것 | 확인 질문 # |  (없으면 "없음")
## 5. 반드시 답할 질문   | # | 질문 | 어느 장·슬라이드에 쓰이나 | 필수/선택 |
## 6. 필요한 근거 종류   질문별 1차 자료 유형
## 7. 예상 구조          DOC 장·절 / PPT 덱 유형 흐름과 장수 — 가안
## 8. 검증이 필요할 주장  틀리기 쉬운 것 (유리의 출발점)
## 9. 요르에게 주의사항   접근 제약·피할 출처·기준 시점 (없으면 "없음")
```

## 3. 완료 게이트 — 검토해 줄 사람이 없다. 직접 확인한다
- 질문에 다 답하면 §7 구조가 채워지는가? 빈 장이 생기지 않는가?
- 잠정 답이 기대는 사실을 「확인할 전제」에 적고, 전제마다 §5 질문이 붙었는가? 전제는 01·00에서 사실처럼 쓰지 않는다. 설명·기록·안내에 입증할 주장을 억지로 만들지 않는다.
- 목적에 답하지 않는 질문이 섞이지 않았는가? 범위가 과하지 않은가?
- DOC는 선택한 글 유형의 필수 재료와 보조 목적의 필요한 재료가 질문에 포함됐는가? 비교가 필요할 때 비교 기준을, 설득에는 대안·반론을 묻는다. 수치 질문에는 기준 시점·집계 범위를 붙인다.
- (발표에 캐릭터·인물이 나오면) 공식 외형 묘사를 확보하라는 질문이 있는가?
- 사용자가 쪽수를 지정했으면 **들어갈 수 있는 양인지 먼저 검산한다**(E-052). 안 들어가면 질문 수나 §7 구조를 지금 줄이고,
  그래도 안 되면 01을 내기 전에 사용자에게 올린다. 다 쓴 뒤 분량 때문에 근거 있는 내용을 빼지 않는다.
- 독자가 주제를 모를 수 있으면(학술·브리핑 덱, DOC) 핵심 인물·용어의 정의를 확보하라는 질문이 있는가? 검증 뒤에는 조사하지 않는다.

## 4. 기획이 교정되는 두 자리
요르의 기획 보정 제안(02 §H, 최대 3건 — 전제 판정 포함)과 유리의 01↔02 대조(05 §4)다. 방어하지 말고 근거를 본다. 전제가 뒤집히면 05를 기다리지 말고 02를 받은 즉시 방향을 정한다.
채택하면 개정 번호를 올린다(`CLAUDE.md` §5).
