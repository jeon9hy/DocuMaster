# 절차 — 조사 (요르) · 출력 `02_research_pack.md`

근거 유형·확인 상태·수치 조건·출처 충돌·할루시네이션 유형은 `공통/근거정책.md`에 있다. 여기서 반복하지 않는다.

## 1. 범위

`01_research_blueprint.md`의 **조사 질문에 답하는 것**이 목적이다. 백과사전을 만들지 않는다.

- **발견 레인(최대 3건):** 기획을 바꿀 만큼 중요한데 질문에 없는 발견이 있으면 §H에 제안한다.
  근거 ID와 왜 기획을 바꿀 만한지 한 줄씩 적는다. 없으면 "없음"이라고 쓴다. 채우려고 만들지 않는다.
- 목적에 따라 더 조사할 것 — 설득·제안: 예상 반론 / 사내 보고: 비교 기준 / 정책·시장: 제도 현황과 시행 시점 /
  학술·기술: 방법의 한계와 상반된 연구.
- 발표 모드이고 캐릭터·인물이 나오면, 공식 외형 묘사(색·형태·식별 특징)를 근거로 확보한다. 06B의 Character Model이 이것만 쓸 수 있다.

## 2. 출력 형식 — 바꾸지 않는다 (로이드는 헤더만, 유리는 절 기호로 대조한다)

```markdown
# Research Pack
- 작업 ID / 조사 버전 / 적용 기획 개정 번호 / 모드:
- 참고자료 읽은 범위 / 못 읽은 범위 (없으면 "참고자료 없음"):
- 웹 검색 사용 가능 여부:
- 근거 확인: 외부 n/n · 로컬 n/n · 계산 n/n
- 기획 보정 제안: n건 · 미확인 필수 항목: n건
--- 헤더 끝 ---

## A. Executive Findings      핵심 5~8줄, 줄마다 근거 ID
## B. Detailed Findings       ### Q1. <질문> — 답 / 근거 ID / 확인 상태 / 남은 불확실성
## C. Evidence Table          값과 조건의 원본. 다른 절은 ID로 참조한다
| ID | 주장 | 출처 제목 | 발행 주체 | 발행일 | 근거 위치 | 확인 상태 | 비고(값·단위·시점·범위·본문 구절) |
## D. Conflicting Evidence    항목 / 각 값과 조건 / 차이 원인 / 채택 보류 — 로이드 판단
## E. Unverified Claims       항목 / 못 한 이유 / 필수 여부 / 필요한 확인
## F. Important Numbers       | 값 | 단위 | 기준 시점 | 집계 범위 | 근거 ID |
## G. Sources                 ID · 제목 · 발행 주체 · 발행일 · URL(접속일) · 1차/2차
## H. 기획 보정 제안           발견 / 근거 ID / 확인 상태 / 이유 / 제안 조치 (없으면 "없음")
```

결과물 구조(장·절, 슬라이드)는 여기서 짜지 않는다. 그건 06에서 한다.

## 3. 제출 전 점검

근거정책 §6을 네 원고에 대고 훑은 뒤 아래를 확인한다 — 모든 질문에 답했는가(답 못 한 것을 답한 척하지 않았는가),
열지 않은 것을 `[확인됨]`으로 적지 않았는가, 수치마다 단위·시점·범위가 있는가, 보간한 값이 없는가,
충돌을 하나로 확정해 버리지 않았는가, §C의 값과 §A·§B·§F의 값이 일치하는가.
