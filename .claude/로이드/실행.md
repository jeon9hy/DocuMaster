# 로이드 실행 절차

호출 직전에 **필요한 절만** 읽는다 — `sed -n '/^## 4\./,/^## 5\./p' .claude/로이드/실행.md`

| 절 | 언제 |
| --- | --- |
| §0 | 경로 · 작업 시작 |
| §1 | 모드 판정 + 00 + 01 |
| §2 | 참고자료 (`자료/`가 있을 때만) |
| §3 | 유리 — 03 → 05 |
| §4 | 요르 — 조사 02 / 응답 04 + 패치 / PPT 세부 기획 06 + 발표팩 07 |
| §5 | (DOC) 아냐 07 → `skills/doc-finish` |
| §6 | (PPT) `skills/deck-review` → `skills/notebooklm-handoff` |
| §7 | 최종 이관 |

## 0. 경로 · 시작
```bash
ROOT="$(pwd -W)"     # 프로젝트 루트에서. C:/... 형식(E-012)
ID=<주제_YYYYMMDD>; MODE=문서|발표; TYPE=스토리|브리핑|학술   # TYPE은 발표만 — 00의 덱 유형
mkdir -p "작업/$ID/workspace" "작업/$ID/sources" "작업/$ID/references" "작업/$ID/output"
```
python에 절대경로를 넘길 때는 `C:/...`로 쓴다(E-012). `상태.md`는 `로이드/상태파일.md` 양식으로 만든다.

## 1. 모드 판정 + 00 + 01
모드를 판정하고(애매하면 한 번 묻는다) `00`과 `01`을 **직접, 이어서** 쓴다. 에이전트는 부르지 않는다.
```markdown
# User Brief
- 작업 ID / 모드 / 작성일
- 원문 요청: (그대로)
--- 헤더 끝 ---
## 목적 · 결과물(형식·분량) · 주요 요구사항 · 대상 독자 · 필수 포함 · 제한사항
## 디자인 방향
- 덱 유형(PPT): 스토리 / 학술 / 브리핑 — 판정 근거 한 줄 (`공통/발표_<유형>.md` 하나만 싣는다)
- 톤: 전문적 ↔ 친근 ↔ 귀엽고 아기자기
- 이미지 비중: 높음 / 중간 / 낮음 · 이미지 방식: 사용자 제공 / 생성 일러스트(PPT만) / 데이터·도식
- 캐릭터·인물 그림(PPT): 허용(초안용) / 금지 · 레퍼런스: references/ 경로 또는 "없음"
```
- 요구를 넓히지 않는다. 사용자가 말하지 않은 것은 `[추론]`으로 표시한다.
- **디자인 방향은 주제에서 추론하고, 사용자가 말하지 않은 제한을 만들지 않는다**(E-029). 스토리는 친근·이미지 높음·생성 일러스트, 학술은 전문적·이미지 낮음·데이터·도식, 브리핑은 전문적·데이터가 기본이다.
- **덱 유형은 소재가 아니라 목적으로 고른다**: ① 사용자가 말한 유형 ② 발표 맥락(수업·학회·경영진 보고·교육) ③ 목적 ④ 청중이 할 일 ⑤ 소재.
  위가 정해지면 아래로 바꾸지 않는다. ①~④가 비어 소재로만 정해야 하면 한 번 묻는다.
  예: 세미나에서 캐릭터 서사 분석 → 학술 · 논문으로 경영진에게 대응안 보고 → 브리핑 · 작품 세계관을 흥미롭게 소개 → 스토리
- 이어서 `로이드/기획.md`로 `01`을 쓰고 그 §3 게이트를 통과해야 요르를 부른다.

## 2. 참고자료
```bash
python -c "
import fitz; d=fitz.open('자료/<파일>.pdf'); print('페이지',d.page_count)
for i in [0,d.page_count//2,d.page_count-1]: print(i+1,len(d[i].get_text()),'자 / 이미지',len(d[i].get_images()))"
```
텍스트가 0자인 구간은 dpi=150 PNG로 `작업/$ID/sources/<자료명>_pNNN.png`에 둔다. 위치는 PDF 기준 페이지로 적는다.

## 3. 유리 — 검증
**모델 값**: 각 요르·유리·아냐 호출 직전에 `DOCUMASTER_AGENT_MODELS`가 가리키는 JSON을 다시 읽어
`yor.model`·`yor.effort`·`yuri.model`·`anya.model`을 그대로 쓴다. 이전 호출의 변수·기억값을 재사용하거나 다른 값으로 대체하지 않는다.
환경변수가 없을 때만 기본값 — 요르 `gpt-5.6-sol`·`xhigh`, 유리 `sonnet`, 아냐 `opus`. 파일 경로나 상위 폴더 이름이 임시·스모크처럼 보여도 웹앱이 넘긴 파일은 **현재 실행의 권위 있는 스냅샷**이다. 이름을 근거로 무시하거나 기본값으로 바꾸지 않는다. 파일이 있는데 읽을 수 없거나 필드가 빠졌으면 호출하지 않고 오류를 보고한다(웹앱이 실행 기록과 대조한다).
```
Agent(subagent_type:"general-purpose", model:<유리 모델>,
  prompt: <.claude/유리/검증.md 전문> + "이번 호출: 03. .claude/공통/근거정책.md 를 읽어라.
          입력: ./작업/<ID>/workspace/00_user_brief.md · 01_research_blueprint.md · 02_research_pack.md")
```
받은 전문을 `03_verification_questions.md`로 저장하고 에이전트 이름을 `상태.md`에 적는다.
판정은 **같은 에이전트에** 보낸다 — `SendMessage(to:"<유리>", message:"이번 호출: 05. 입력: ./작업/<ID>/workspace/04_verification_answers.md (+02_research_pack_v02.md)")`.
에이전트가 이미 끝났으면 새로 띄우고 파일과 경로를 전부 다시 준다.
유리 호출이 반환한 에이전트 ID는 첫 응답 직후 `상태.md`의 `유리 에이전트`에 기록한다. `(미실행)` 같은 자리표시자를 완료 시점까지 남기지 않는다.

## 4. 요르 (Codex)
### 4-0. 공통
- **각 호출 직전에 모델 JSON을 다시 읽어 `YM=yor.model`, `YE=yor.effort`로 정하고 `-m $YM -c model_reasoning_effort=$YE`를 항상 붙인다.** 빠지면 기본 모델·medium으로 조용히 돈다. PowerShell에서는 `codex.cmd`(E-009).
- 웹앱의 비대화형 로이드 턴에서는 Codex를 `&`·`Start-Process` 등으로 백그라운드에 보내지 않는다. 아래 파이프라인을 포그라운드에서 끝까지 기다린다. 로이드가 먼저 종료되면 웹앱은 실패로 판정하고 자식 Codex가 고아 프로세스로 남는다.
- Bash 도구가 긴 Codex 호출을 시간 제한 뒤 자동 백그라운드화하면 새 호출을 만들거나 턴을 끝내지 말고, 반환된 작업 ID를 `TaskOutput(block:true)`로 완료까지 기다린다.
- 새 세션은 `-C "$ROOT" -s read-only`로 연다(`resume`에는 없다, E-007). 조사 세션은 02→04, PPT일 때만 기획 세션은 06→07이다.
  새 세션을 열면 `grep -m1 '^session id:' <log>`로 실제 ID를 즉시 `상태.md`에 적는다. `(실행 후 기록)`을 남긴 채 다음 단계로 가지 않는다. `--last`는 쓰지 않는다.
- 백그라운드 실행에는 파이프를 걸지 않는다(E-010). 종료 코드와 출력 파일 내용을 **함께** 확인한다(E-030).
- 입력 파일 `작업/$ID/_입력_*.md`에는 **경로와 지시만** 적는다 — 작업 ID / 모드 / 개정 번호 / 호출 종류 / 읽을 경로 / 할 일.
- 사용량 한도(E-013)에 걸리면 모델을 바꾸지 말고 기다리거나 사용자에게 올린다.

### 4-1. 조사 02 — 조사 세션 시작
요르는 읽기 전용이므로 출력 파일을 도구로 직접 만들지 않는다. 완성된 전문을 마지막 응답으로만 내며, Codex CLI의 `-o`가 그 응답을 `02_research_pack.md`에 저장한다.
```bash
cat .claude/요르/역할.md .claude/공통/근거정책.md .claude/요르/조사.md 작업/$ID/_입력_조사.md \
  | codex.cmd exec -m $YM -c model_reasoning_effort=$YE --skip-git-repo-check -C "$ROOT" -s read-only -c tools.web_search=true \
      -o 작업/$ID/workspace/02_research_pack.md - > 작업/$ID/_log_02.txt 2>&1
```
참고자료 스캔본은 `-i`로 4~6장씩 붙인다.

### 4-2. 응답 04 + 패치 — 조사 세션 resume
```bash
cat .claude/요르/검증응답.md 작업/$ID/_입력_응답.md \
  | codex.cmd exec resume <조사 세션 ID> -m $YM -c model_reasoning_effort=$YE --skip-git-repo-check -c tools.web_search=true \
      -o 작업/$ID/_raw_04.md - > 작업/$ID/_log_04.txt 2>&1
python .claude/tools/apply_patch.py --answers 작업/$ID/workspace/04_verification_answers.md \
  작업/$ID/workspace/02_research_pack.md 작업/$ID/workspace/02_research_pack_v02.md 작업/$ID/_raw_04.md
```
적용기는 하나라도 실패하면 아무것도 쓰지 않는다. 구분자가 없거나 적용에 실패하면 메시지를 요르에게 그대로 돌려준다(1회).
적용한 뒤 헤더 수치와 절 사이 값이 일치하는지 본다.

먼저 05를 채택한다. **DOC는 요르 기획 호출 없이 §5로 간다.** PPT만 아래를 진행한다.

### 4-3. PPT 세부 기획 06 — 기획 세션 **새로 시작**
05 §4의 출처 충돌과 기획 보정을 결정해 `_입력_세부기획.md`에 적는다.
조사 세션은 resume하지 않는다(조사 대화 재적재와 미검증 사실 유입, E-029).
```bash
cat .claude/요르/역할.md .claude/요르/세부기획.md .claude/공통/발표규격.md .claude/공통/발표_${TYPE}.md 작업/$ID/_입력_세부기획.md \
  | codex.cmd exec -m $YM -c model_reasoning_effort=$YE --skip-git-repo-check -C "$ROOT" -s read-only \
      -o 작업/$ID/workspace/06_detailed_plan.md - > 작업/$ID/_log_06.txt 2>&1
```
**완성도 게이트** — 기계 검사부터 돌리고, 06 전체를 읽는다.
```bash
python .claude/tools/gate_check.py "$ID" 06     # FAIL은 돌려보내고 CHECK는 닫은 이유를 기록.md에
```
FAIL(되살아난 REMOVE·빠진 CAUTION·LOCKED 위반)은 그 항목만 기획 세션에 PATCH로 돌려보낸다. 05에 없는 수치는 근거를 대지 못하면 뺀다.
읽으면서는 스크립트가 못 잡는 것을 본다 — `요르/세부기획.md` §4, 표현만 바꾼 REMOVE, 강도.

### 4-4. PPT 발표팩 07 — 기획 세션 resume
```bash
OUT=07_notebooklm_presentation_pack.md
cat .claude/요르/비주얼_발표.md 작업/$ID/_입력_비주얼기획.md \
  | codex.cmd exec resume <기획 세션 ID> -m $YM -c model_reasoning_effort=$YE --skip-git-repo-check \
      -o 작업/$ID/workspace/$OUT - > 작업/$ID/_log_07pack.txt 2>&1
```
`_입력_비주얼기획.md`: 모드 · 브리프 「디자인 방향」 경로 · 자산 경로(`references/`·`자료/`) · 사용자 지정 스타일(없으면 "없음"). 웹 검색은 끈다. 출력이 곧 발표팩이며 §6으로 간다.

**반려는 담당에게 돌려보낸다.** 로이드가 직접 하는 것은 기계적 수정(오탈자·형식·필드 누락·강도 낮추기)과 PPT 화면 문구뿐이다.
반려는 `기록.md`에 한 줄로 남긴다: `대상 · 실패 이유 · 담당 · 요청`.

## 7. 최종 이관 — `최종/<ID>/`
```bash
if rg -n '^## 세션.*(실행 후 기록|\(미실행\))' "작업/$ID/상태.md"; then
  echo "상태.md 세션 자리표시자를 실제 ID 또는 해당 없음(이유)으로 닫아야 한다" >&2; exit 1
fi
mkdir -p "최종/$ID" && cp 작업/$ID/output/$ID.pdf "최종/$ID/$ID.pdf"    # DOC
python .claude/tools/nlm_pipeline.py promote --id "$ID"               # PPT (검사 미통과·팩에 없는 숫자가 있으면 보류된다. 직접 닫았을 때만 --force)
```
DOC는 `최종/_manifest.md`에 `- 날짜 · \`ID\` · 파일명` 한 줄을 덧붙인다(PPT는 도구가 쓴다).
**판정이 passed/conditional이고, 기계 검사를 통과했고, 교차 확인이 닫혔고, CAUTION 문구가 최종본에 있을 때만** 실행한다.
그다음 `상태.md`를 `완료`로 바꾸고 `CLAUDE.md` §7대로 보고한다.
