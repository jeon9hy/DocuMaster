# 덱 유형 — 브리핑 (근거가 말한다)

`발표규격.md`(공통) 위에 더한다. **브리핑 작업에서만 싣는다** — 다른 유형의 규칙은 이 작업에 없다.
언제: 시민 교육·정책·사업·보고 **발표**(제출용 보고서·제안서 문서는 DOCUMENT 모드). 청중이 얻을 것: 현황 이해와 할 일.

## 1. 흐름 — 06 Deck Arc
- 목적에 맞는 갈래 하나를 고르고 00·06·07 헤더에 `- 덱 유형: 브리핑 (의사결정 보고)`처럼 적는다.
  - **의사결정 보고**(청중이 결정한다): 표지 → 핵심 결론·요청 요약 → 현황 → 원인 → 선택지·위험 → 제안·다음 단계 → 출처·한계
  - **설명·교육**(청중이 이해하고 행동한다): 표지(주장·기준일) → 왜 중요한가 → 현황 → 맥락 → 결론·할 일 → 출처·한계
- 역사·비교·통념과 실제 같은 장은 근거가 있을 때만 둔다. 긴 역사 서론·방법론 설명으로 시작하지 않는다.
- 중심 장은 핵심 데이터 장이다. 결론 장은 앞 장의 결과를 묶어 다시 말해도 된다(새 사실은 없다).
- 마지막 장은 출처·확인의 한계다(결론 뒤에 올 수 있는 유일한 장).

## 2. 화면
핵심 숫자·결론·요청이 가장 크게 보인다. **구조는 따르고 겉모습은 주제마다 새로 정한다.** 이 파일의 구조는 사용자 레퍼런스(정치 참여 브리핑 11장, 원본 파일은 없음)에서 뽑았다. 그 덱의 겉모습(흰 바탕·파랑·빨강, 영문 대문자 섹션 라벨,
원 안 아이콘, 둥근 카드)은 기본값이 아니다 — 사용자가 "이 스타일로"라고 할 때만 쓴다.
- 본문은 장마다 패턴 하나, 내용이 고른다. 예: 그래프 + 옆 해석 2~3줄 · 큰 숫자와 기준 · 같은 구조의 병렬 항목 · 연표 · 비교표 ·
  대비 두 칸(통념 ↔ 실제) · 단계(할 일) · 결론 문단 · 출처·한계 두 칸. 같은 패턴은 2장 연속 금지, 덱 전체 2회까지. 같은 지표·조직 단위를 비교할 때는 같은 틀을 반복해도 된다.
- 데이터 옆에 해석을 둔다. 숫자에는 기준(연도·집계 범위)을 같은 칸에 붙인다. 그래프는 논점 하나만 초점색이다.
- 병렬 항목이 같은 구조(이름·설명·근거)면 카드처럼 나란히 둔다. 제목을 되풀이하는 박스는 여전히 재작업 대상이다.
- 장식 일러스트·캐릭터·사진풍 그림은 쓰지 않는다. 그림은 대상 자체를 보여 줄 때만.

## 3. 글자
- **모든 본문 장에 주장형 제목 한 줄**(그 장의 결론 문장, 핵심어만 강조). 출처·한계 장은 이름 제목이어도 된다.
- 줄 한도(공백 빼고) 제목 24자 · 화면 문구 한 줄 40자. 항목 설명 2줄, 결론 문단 3~4문장. 짧고 분명한 발표 말투.

## 4. 출처와 한정
- 근거를 쓴 모든 장에 문장형 한 줄: `출처: 기관 「자료명」(YYYY-MM-DD).` 기관의 공식 표기가 있으면 그것을 따른다. 비교의 한계나 단순화한 인과를 같은 줄에 이어 써도 된다.
- 한정은 해당 수치 옆 한 줄. 긴 조건은 발표자 메모와 마지막 출처·한계 장으로.

## 5. 06B 쓰는 법
- Art Direction 색: 배경(내용이 읽히는 이유) · 글자 · 주색 · 초점색(한 장에 한 곳) — 각각 이 주제의 무엇에서 왔는지.
  주제에서 온 시각 장치 하나를 둔다(예: 선거 → 투표용지의 칸, 기후 → 온도 띠). 이전 작업·레퍼런스와 같은 조합이면 이유를 적는다.
- Art Direction 추가 칸: `- 숫자 강조:` 핵심 숫자를 키우는 방식과 붙일 기준 · `- 결론·요청 표시:` · `- 위험·선택지 표시:` · `- 시각 장치:` 주제에서 온 것 하나.
- Character Model은 인물 그림이 있을 때만(발표규격 §5).
- Deck Rhythm 예: `1 표지·주장 부제 → 2 왜 중요한가·병렬 항목 3 → 3 현황·그래프 + 해석 → …`(장마다 Beat · 패턴).
- 「화면」: 주인공은 패턴 이름과 그 데이터. 구성은 패턴 안의 배치(해석 패널·기준 줄의 자리).

## 6. 검수와 생성
- 흐름 질문: 핵심 결론에서 근거와 실행 과제까지 흐름이 분명한가?
- deck-review 화면 문구: 출처는 옮기거나 지우지 않는다. 문장은 짧고 분명하게, 강도는 올리지 않는다.
- NotebookLM `--slide-format`: detailed_deck. 레퍼런스 파일은 "이 스타일로"일 때만 올린다.

## 7. 재작업 대상 (발표규격 §6에 더해)
주제만 있는 제목("현황") · 해석 없는 그래프 · 기준 없는 숫자 · 장식 그림 · 출처 없는 근거 장 · 할 일·결론 없이 끝나는 덱 · 결론·요청을 찾기 어려운 의사결정 보고 · 이유 없이 레퍼런스와 같은 겉모습
